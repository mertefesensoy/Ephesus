# 2026-08-31 — M7.6: shareable hires and profiles

## Problem / Motivation

FR-10.4: *"Shareable hires: export/import a role template via link/file; import
only pre-fills the spawn form — a human always confirms."* ADR-0012 extends it
to whole bundles: *"shareable like hires … and diffable in review since they're
plain files."*

The package's risk line is the design constraint, and it is the whole job:
**an imported profile is UNTRUSTED CONTENT (invariant §13's spirit) — it may not
raise its own privileges on the way in.**

A shared bundle is the most dangerous input this system accepts. It carries env
grant names, autonomy levels for every gate class (including M7.5's new
`outbound`), trigger bindings on a timer, and playbooks — prose that becomes an
agent's instructions. Somebody else wrote all of it.

## Implementation Approach

### Two decisions that shape everything

**The envelope carries FILES, not a parsed bundle.** ADR-0012's argument for
declarative bundles is that they are plain files, diffable in review. An
envelope carrying a re-serialized object would hand the reviewer a diff of the
importer's formatting rather than of what the author wrote, and would round-trip
losslessly only for fields this build happens to know. Carrying the text makes
`export → import` lossless by construction, asserted byte-for-byte.

**The manifest is DERIVED, never trusted.** The envelope carries a manifest —
the disclosure a human reads before confirming. On import it is *recomputed from
the payload by the same function that produced it*, and any mismatch is refused
by name. That single check is what makes the confirmation meaningful: without
it, the human approves a summary the payload is free to contradict, which is not
a gate but a decoration.

It is also what gives "an undeclared env grant" a precise meaning — a hire
quietly asking for a credential the summary did not list.

The manifest declares **every** gate class, including ones the bundle never
mentions and which therefore take its default. A manifest listing only the
explicit overrides would have let a permissive default arrive undisclosed.

### "Widened autonomy" means two things, and both are checked

Activation-time clamping (`composeAutonomy`) already stops a profile exceeding
the global ceiling. That does not cover the sharper case: **a shared bundle
reusing a name the Architect already trusts, arriving with more authority than
the version it replaces.** The global ceiling might legitimately be high; the
point is that this profile's own request grew without anyone deciding it should.

So `inspectImport` also compares against what is installed under that name and
refuses a raise of any class, or any new env grant. Narrowing is allowed — a
shared bundle that tightens a profile is what a security fix looks like.

### Import pre-fills; install writes; neither activates

Three separate steps, and the separation is the requirement:

- `inspect` reads a blob and returns a disclosure. Asserted pure by a **census
  of the file tree before and after**, not by a claim.
- `install` is what a confirmed form reaches. It writes files into the harness
  home — never beside the built-ins, so a shared bundle cannot shadow one that
  ships with the app.
- **Activation remains `profiles:activate`**, a separate Architect action.

Asserted on the API surface, the S-SECRETS way: the set of sharing channels is
pinned, so a future channel that imported-and-activated in one call fails by
name. `HireExchange` has no spawn, scheduler or activation seam at all — there
is nothing on it to call, which is stronger than a flag saying not to.

### One list of secret shapes, in two places, provably

`scripts/check-invariants.cjs` has carried the credential patterns since M0 as a
build gate; it is a standalone `.cjs` that runs before anything compiles, so it
cannot import a TS module. Duplicating a security list normally means drift, and
the half nobody updated is the half that stops catching things.

`test/shared/secret-shapes.test.ts` reads the checker as **text** and compares
the lists element by element. The duplication is real; what is removed is the
possibility of it going unnoticed.

The detector returns the credential's *name*, never the matched text — a refusal
that quoted the secret would copy it into the log and any bug report it is
pasted into, turning a caught leak into a wider one.

## Mathematical / Statistical Details

The prose digest is **FNV-1a**, 32-bit, over the sorted list of every hire brief
and playbook body:

```
h ← 0x811c9dc5
for each part p (sorted):
    for each char c in p:  h ← (h XOR c) × 0x01000193  (mod 2³²)
    h ← (h XOR 0x2f) × 0x01000193                       (separator)
digest = "fnv1a-" + hex(h)
```

Sorting makes it order-independent, so a reordered bundle is not reported as
changed prose. The separator byte prevents `["ab","c"]` and `["a","bc"]`
colliding.

**It is not a signature and must not be read as one.** Nothing here
authenticates an author or resists a determined forger; a 32-bit digest has
collisions by construction. The manifest is recomputed from the payload on
import, so the digest's only job is to make *"the instructions are not the ones
you approved last time"* visible to a human. A SHA-256 would imply a guarantee
this design does not make.

## Design Decisions

**A hire is addressed through its bundle** (`exportHire(profile, hire)`). Hire
templates live inside bundles; a bare-name address would need a second, flatter
place they live, and two places is how the org layer's versioning starts
disagreeing with the bundle's.

**An invalid bundle is not exported.** Sharing one spreads a refusal rather than
a profile, and the importer's reasons would describe a mistake the exporter
could have seen first.

**`install` re-inspects the blob it is handed.** Whatever a caller inspected
earlier, the blob being written is the one judged — inspect-then-install-
something-else is precisely the confusion this package exists to prevent.

### Five defects found by an adversarial pass, before shipping

A four-lens adversarial review ran against this module *while it was being
written*. It found five real privilege escalations in my own code. All five are
fixed, and each has a regression named for it.

| # | Defect | Why it mattered |
|---|---|---|
| 1 | **Path traversal in payload file names.** Record keys were bare `z.string()`; `install` writes with `path.join`, which resolves `..`. | A playbook named `../../../gate-policy.json` overwrites the Watch's policy — SDD §2 says that file "can only ever loosen, never tighten". Complete bypass of the approval system. |
| 2 | **JSON `\uXXXX` escapes defeated the secret scan.** The scan read the raw blob text. | The raw text matches nothing while `JSON.parse` decodes a real token. The scan now walks decoded values *and keys*. |
| 3 | **`install` merged instead of replacing.** | A v2 dropping a hire or trigger left the old one on disk; the loader read back the *union*. The Architect confirms two hires and gets three — with the third still armed. |
| 4 | **The widening check was skipped when the installed profile did not parse.** | A bundle arriving while the installed copy is broken got *more* latitude than one arriving while it is healthy. Now refused: "we cannot tell what this name may do" is a reason to stop. |
| 5 | **The manifest disclosed names but not prose.** | Every name identical, every runbook rewritten — and a playbook is the agent's task list, on a timer, with the profile's autonomy. Closed by the prose digest. |

Defect 1 is the one worth remembering: it was found by a probe that wrote a
traversing filename and asserted the import *succeeded*. The happy-path suite
was green throughout.

no test can reach is indistinguishable from one that is not there).
