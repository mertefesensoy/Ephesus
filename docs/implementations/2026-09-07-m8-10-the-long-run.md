## 1. Problem / motivation

Every previous M8 package fixed something you could see going wrong. This one
fixes five things that are **invisible at fixture scale**: each was found by
measuring a synthetic multi-day run, and a unit test over a ten-line log passes
against all five. They are what the harness does to itself when it is simply
left running.

| Item | The defect |
|---|---|
| **D3** | No log rotation. Every read parsed `log.jsonl` from byte zero — measured at 28.4 MB and 306 ms per parse **on the main loop**, the loop that also carries PTY bytes and hook events (SDD §11, NFR-1/NFR-2). |
| **D4** | `sessionIds` only ever grew. The Watch folds a transcript per id, twice a tick, re-reading each file in full: 72 ms today, roughly a second per agent per tick after a week. |
| **D5** | Mail addressed to an agent with no session was delivered and silently never read. |
| **D6** | `ReflectionJob.sweep()` iterated `reachableAgents()` with no try/catch, so one throwing agent stopped reflection for every agent after it. |
| **D10** | The roster's `profile` field was hard-coded `null` at both write sites, so nothing downstream could ever ask which profile hired an agent. |

The register was dated, so **D5 was verified by execution before anything was
built for it** — see §3.5. Three others were confirmed still open by the
Architect on the same day and taken as given.

## 3. Implementation approach

### 3.1 D3 — rotation moves bytes, and changes nothing about what is readable

The register named the hazard itself. `src/shared/incident-view.ts` (M8.9)
**drops an incident whose `raised` row is missing**. A rotation that left that
row in an archive nobody read would not produce a truncated incident panel — it
would produce an **empty** one, with the incidents still open and nothing in the
company saying they had ever existed.

So the readers were enumerated before a line was written:

| Reader | Where | Needs |
|---|---|---|
| Incident board | `index.ts` — `foldIncidents(agora.readLogAll())` | whole history |
| Standup facts | `index.ts` — `readLogSince(sinceSeq)` | whole history from a cursor |
| Org metrics | `index.ts` — `readLogAll()` | whole history |
| Gymnasium history | `index.ts` — `readLogAll()` filtered to `gym` | whole history |
| Degradation replay | `index.ts` — `tailLog(DEGRADATION_REPLAY_LIMIT)` | newest N |
| Activity feed | `ipc.ts` — `readLog(afterSeq, limit)` / `tailLog(limit)` | a page, and newest N |

The answer is the same for all six, so **none of them changed**. The read path
spans sealed segments and the live file, `readLogAll()` returns exactly what it
returned before rotation existed, and rotation is invisible above the `Agora`
seam.

**Invariant §5 across the boundary.** Rotation is a `rename` and nothing else:
no rewrite, no compaction, no truncation, not one byte of an entry altered or
dropped. The concatenation of the segments and the live file *is* the file that
used to be there, in the same order.

**What the win actually is**, given that no reader reads less:

1. **A bounded live file.** Appends stay cheap, and git stops storing a whole
   new multi-megabyte blob on every commit — a sealed segment is one blob,
   once, forever.
2. **Segment skipping with no I/O to decide it.** Each segment is named for the
   first `seq` it holds (`log-000000000001.jsonl`), so the range it covers is
   known from the filenames alone. A cursor read skips every segment it is past
   without opening it; `tailOf` walks backwards from the live file and stops as
   soon as it has enough.

**The boot reconcile.** `open()` recovers the sequence from the *archive* when
the live file is empty or absent. Without that, a restart landing just after a
rotation recovers `seq = 0`, renumbers from 1, collides with archived entries,
and rewinds every cursor-based reader to the beginning of time.

**Rotation never costs an event.** A rotation that cannot happen (the archive
directory is unwritable) is skipped and the append proceeds into the file that
is already there. A large file is a performance problem; an append that throws
because housekeeping failed is a lost event.

### 3.2 D4 — the retention rule, and why a trim cannot lose money

The register framed this correctly as a **correctness question about spend**
before a performance one: a trimmed id is a transcript the budget can no longer
read. The rule is *keep the newest eight, drop from the front*, and it is safe
for two reasons that must hold together:

1. **Folded spend is durable.** `CostLedger.fold` keeps a per-`(agent, source)`
   cursor and `spendFor` totals rows read back out of the store (invariant §11).
   Dropping an id forgets where to look for *more*, not what was already found.
2. **Only the newest session can still grow.** Resume targets
   `sessionIds.at(-1)`, and an engine writes the session it is running — so
   trimming from the **front** can only ever drop finished transcripts.

The owed test asserts the **spend**, not the rule: twelve sessions folded, four
ids trimmed, every token still counted.

### 3.3 D6 — the throw was never hypothetical

`ask()` composes a real `Message`, and `messageSchema` caps `body` at 200 000
characters. An agent whose condensing sections exceed that cap therefore throws
**on validation**, inside the unguarded loop. Iteration order is
`reachableAgents()`, which is sorted — so one oversized memory silently stopped
reflection for **every agent after it alphabetically**, every hour, for as long
as the memory stayed oversized. The agents that lost their reflection were
chosen by their names.

The guard wraps the whole of one agent's turn (the plan, the retry decision and
the ask), because which call failed does not change what the sweep must do. The
failure is reported per agent, naming the agent and the reason, and `sweep()`
returns a report so *"reflection stopped for six agents"* is a claim a test can
make. The test drives the real path — an oversized memory, with its own case
asserting the body genuinely exceeds the cap. A stub that threw would have
proved only that a `try`/`catch` catches.

### 3.4 D10 — resolved once, because the two write sites do not have the same view

The fix is *not* "ask the resolver at both sites". `onRosterChange` **replaces**
the entry, and the second site runs on lifecycle changes including the exit — by
which time the instance may have been released, so a fresh lookup would answer
`null` and erase what the hire recorded. That is the same erasure the `budget`
field on the very next line is already commented to avoid.

So it is resolved once, while the activation plan is still in flight and
`planFor` can answer (M8.7b put in-flight plans in `activating` for exactly this
reason), and carried on the live agent. An agent does not change profile during
its life, so one resolution is the whole truth.

The value is the profile **name**, not the instance id: SDD §4.1 caps the field
at 64 characters and documents it as the profile, while an instance id is
`<profile>@<targetRef>` and carries a target the field does not claim to hold.

### 3.5 D5 — verified open by execution, then made audible

`main` carries `f6c9262` and the merged `fix/mail-lost-when-a-woken-agent-dies`,
either of which might have closed this. A probe against the real router settled
it:

```text
delivered: 1   rejected: 0
still pending in the dead agent inbox: [ '...json' ]   (after three wake ticks)
nudged: []
log rows: delivery/
rows naming the problem: 0
```

Both existing fixes address the agent that **comes back**. Nothing addressed the
one that does not.

The question the watchdog could not ask is *"is there a process at all"*.
`isIdle` is false for a busy agent **and** for a gone one, so "ask later" and
"nobody is ever going to read this" arrived as the same silence. `hasSession` is
that question, checked **before** the idle test.

**The mail is not bounced and not dropped.** An agent can come back — the
respawn ladders exist for that — and its inbox is where its mail belongs until
it does; bouncing would break the one case the ladder was built for. What was
missing is not delivery, it is **disclosure** (invariant §7): a row in the book
of record so the condition survives a restart, and a degradation so the
Architect sees it now.

Reported once per stranded **set** rather than per tick, because the sweep runs
every second. Holding the set rather than a flag is what lets new mail for a
still-silent agent be heard.

## 4. Numeric details

### 4.1 The rotation threshold, derived rather than chosen

`ROTATE_AT_BYTES = 4 MiB`. From the register's measurement — 28.4 MB parsed in
306 ms, so ≈ 11 ms per MB — a 4 MB whole-live-file parse costs ≈ 45 ms, the same
order as the `slowReadMs` threshold the Agora already treats as the edge of
acceptable on the main loop.

### 4.2 What rotation buys, measured

**Fixture, so the numbers carry their condition:** two logs with identical
content, built through the real `EventLog.append` — one that never rotates (the
behaviour before this package) and one at the shipped 4 MiB. Padded to
**28.0 MB across 29 196 entries**, matching the reported production size. Median
of three runs, on the Architect's machine.

| Reader | Unrotated | Rotated |
|---|---:|---:|
| `tailLog(200)` — the Activity feed, per poll | 200.0 ms | **26.2 ms** |
| `readLogSince(recent cursor)` — the standup | 150.2 ms | **20.8 ms** |
| `readLogAll()` — org metrics, incident board | 170.9 ms | 178.0 ms |

History preserved: **29 196 entries readable both ways, identical seq
sequence.**

The `readLogAll` row is the honest cost of the design and is reported rather
than hidden: the whole-history read now opens eight files instead of one, for
about 4% more. It is precisely the read that must not get cheaper by seeing
less.

### 4.3 The test fixtures

- `log-rotation.test.ts` — entries padded to 512 bytes, rotating at **64 KiB**,
  about 1 500 entries across three sealed segments plus a live file. At the
  shipped 4 MiB threshold the identical suite took **99 seconds**; at 64 KiB it
  takes 6.5. `rotateAtBytes` is a constructor option (the same shape the Agora
  already uses for `slowReadMs`), and two cases stop that convenience becoming
  the shipped value: one asserts `ROTATE_AT_BYTES` is 4 MiB, one builds an
  `EventLog` with no options and proves it has *not* rotated well past the test
  threshold.
- `log-readers-across-rotation.test.ts` — a real `Agora` rotating at 32 KiB.
  Each case **asserts its own premise**: that the row it cares about has
  genuinely left the live file. A test that did not check that would pass having
  proved nothing.

### 4.4 The git observation, and why nothing was added

The register listed the Agora's git at "2 547 loose objects, no packs and no
`gc`", which invites adding a `gc` call. Checked rather than assumed: the Agora
commits through porcelain `git commit`, which **already** runs `gc --auto`, and
`gc.auto` is unset — so git's default of **6 700** loose objects governs, and
2 547 is simply below it. Nothing is missing; no call was added.

What *was* wrong is the **size** of those objects: a 28 MB `log.jsonl`
re-committed produces a whole new multi-megabyte blob every time. Rotation fixes
that at its source, because a sealed segment is written once and never changes.

## 5. Design decisions

| Decision | Alternative rejected | Why |
|---|---|---|
| Rotation preserves every reader's view | Rotate and let old history fall out of the panels | A rotation that quietly makes the company's own history unreadable is worse than no rotation. `incident-view.ts` would have shown an *empty* board. |
| Segments named for their first `seq` | An index file, or reading each segment to find its range | The range is then known from the filenames alone, so a cursor read skips segments with **no I/O**. An index file would be a second source of truth that can disagree with the directory. |
| Rotate before the append | A background timer, or rotate after | The only writer is synchronous, so rotating here seals at an entry boundary by construction rather than by luck. |
| A failed rotation is skipped, not thrown | Propagate the error | A large file is a performance problem; a lost event is a correctness one. |
| Keep the newest 8 session ids | Keep 2 (the argument's minimum); keep all and bound only the read | Two satisfies the safety argument; eight adds margin for engines that fork or interleave sessions in one spawn, and being wrong there costs a lost fold while being generous costs seven file reads. Bounding only the read would leave two mechanisms where one suffices. |
| The profile is resolved once, at hire | Ask the resolver at each roster write | `onRosterChange` replaces the entry, and the exit-time write can run after the instance is released — it would answer `null` and erase what the hire recorded. |
| Stranded mail is reported, not bounced | Bounce to the sender; divert to the human queue | An agent can come back; its inbox is where its mail belongs until it does. Bouncing breaks the respawn case. |
| `hasSession` absent means "cannot tell" | Default to "no session" | An unknown must not manufacture a degradation. The production wiring is asserted by its own test so the opt-in cannot silently go unwired. |

## 6. What the mutation pass found

**28 mutations over every guard this package adds: 27 killed, 1 survivor — and
the survivor is the one written to survive.**

| Group | Killed |
|---|---|
| D6 — reflection guard | 4 / 4 |
| D10 — roster profile | 4 / 4 |
| D4 — session retention | 4 / 4 |
| D3 — rotation | 8 / 8 (+1 control) |
| D5 — stranded mail | 7 / 7 |

**Three survivors on the first pass, all read before any test was touched.**

1. **The cursor skip, widened from `afterSeq + 1` to `+ 2`.** That drops a
   segment whose *last* entry is the very next one the caller asked for. It
   survived because every cursor in the suite sat in the middle of a segment —
   and the standup's cursor is wherever the last brief ended, an arbitrary seq
   that lands on a boundary as readily as anywhere else. The replacement
   asserts, around **every** boundary, that a cursor read equals filtering the
   whole history.

2. **The refusal to seal onto an existing segment, deleted.** `renameSync`
   replaces its destination silently, so that is a sealed segment destroyed —
   history rewritten, which invariant §5 forbids outright. It survived because
   the harness cannot reach that state on its own: `seq` only rises, so a second
   rotation never computes a name it has used. The honest conclusion was *not*
   that the guard is equivalent. The state arrives from **outside** — a restore
   from backup, a file-sync client putting a segment back, or the second process
   pointed at one home that this module's own contract already takes seriously —
   so the test builds it directly, because how it arises is not what the guard
   is responsible for.

3. **A deliberate no-op**, included so the harness has to prove it can still
   report a survivor. It did.

**A fourth survivor appeared in the D5 group and was also a missing test.**
Deleting `strandedReported.delete(agentId)` from the nudge path survived,
because the first test sent *new* mail after the agent returned — a different
filename, hence a different signature, reported either way. The real case is
tighter: `consumeInbox` hands mail to a session by renaming it into
`.inflight/`, and the exit seam returns it under the **same filename** (the
mechanism `f6c9262` added). So mail handed to a session that died holding it
strands again with a **byte-identical signature**, and a record that was never
cleared would have swallowed it — going quiet exactly when it matters most. The
replacement drives that path through `forgetSession`.

## 7. Verification

### 7.1 The gate

```bash
npm run typecheck && npm run lint && node scripts/check-invariants.cjs && npm run test:coverage && node scripts/check-coverage.cjs && node scripts/check-readme-current.cjs
```

All green:

- **typecheck** — four projects, clean.
- **lint** — ESLint zero warnings, Prettier clean.
- **invariants** — `reachability 179/187 src modules reached, 8 unreachable by
  recorded decision, 6 type-only`.
- **suite** — **218 files / 4 096 passed / 0 failed / 8 skipped.**
- **coverage** — exit 0. Statements 76.04%, branches 69.44%, functions 64.64%,
  lines 77.37%.
- **README currency** — current for M8.

### 7.2 The coverage gate caught an untested new function

`check-coverage.cjs` failed the `company` subsystem on branches (92.2% vs 92.63%)
and functions (93.9% vs 94.48%) immediately after D10 landed. The cheap
hypothesis was tested before reaching for attribution-by-argument: a new public
method, `ProfileActivations.profileFor`, with **no test** — because the D10 tests
*inject* that seam into `AgentManager` and therefore never exercise the real
resolver. Testing it cleared both floors on the next run, which settles the
attribution by execution.

No floor was lowered and no ratchet was taken.

### 7.3 Reproducing the D3 measurement

The measurement in §4.2 is reproducible from `src/main/eventlog.ts` alone: build
two `EventLog`s over the same appends, one with
`{ rotateAtBytes: Number.MAX_SAFE_INTEGER }` and one with the default, pad
entries to ~900 bytes until the file reaches 28 MB, and time `tailOf(200)`,
`read(cursor, ∞)` and `all()` on each. The history-preservation check is
`flat.all()` and `rotated.all()` yielding the same seq sequence.

### 7.4 What was NOT proved

**The live app was not started.** `npm run dev` boots the real harness against
the Architect's own `~/.ephesus`, spawning agents and spending tokens, which is
not a side effect to take unattended. Everything above runs against real
filesystems in temp directories, real `Agora` instances, the real router and the
real `EventLog`; the D5 verification ran against the real `Hermes`.

**Rotation has not yet been observed on a live 4 MiB log**, only on synthetic
logs at the shipped threshold (§4.2, 28 MB, seven segments) and at reduced
thresholds in the suite. The mechanism is byte-identical in both.

## 8. Record repair

`docs/DECISIONS-LOG.md` carried a literal NUL at byte 379 988 and a literal
backspace at 380 068 — inside the 2026-09-07 entry that **warns about exactly
this**. The consequence was not cosmetic: `grep` classified the whole file as
binary, so `grep "2026-09-07" docs/DECISIONS-LOG.md` printed *"Binary file
matches"* and no lines at all, and the book of decisions could not be searched
with the ordinary tool. Repaired byte-precisely to the escapes that were meant,
so nothing else in the record moved. The file now returns its matching lines and
carries zero control characters.
