# M0 — Skeleton shell (M0.1–M0.5)

**Date:** 2026-08-26 · **Milestone:** M0 (docs/IMPLEMENTATION.md) · **Author:** the Architect (agent-assisted session)

## Problem / Motivation

The repository was a documentation suite with zero code. M0 turns the contract into a
running Electron shell proving the four load-bearing verticals end-to-end: the typed
preload bridge, a real PTY streaming to a real terminal, the Pixi floor with
spec-conformant motion, and durable app state — so every later milestone builds on
verified plumbing instead of assumptions.

## Implementation Approach

- **Three-tier trust architecture** (SDD §1): main owns all state and validation;
  preload is a thin typed forwarder kept free of runtime dependencies (a sandboxed
  preload cannot `require` external modules — discovered live when zod broke the
  bridge and validators moved firmly to main); the renderer is a projection that
  shows a visible "bridge unavailable"/config-warning state instead of any silent
  fallback.
- **Validator pattern**: every schema'd payload has a zod schema in `src/shared/`
  with `schemaVersion` as a literal and `.strict()` objects, so unknown (possibly
  secret-shaped) keys are rejected at the boundary.
- **PTY vertical**: bytes flow unwrapped over per-id channels (`pty:data:<id>`);
  the renderer subscribes before the shell spawns, eliminating the lost-first-prompt
  race by ordering rather than buffering.
- **Floor vertical**: motion is a pure module (`walk.ts`) — 250 ms/tile, progress
  quantized to 5 steps/tile (UI-DESIGN §6 "stepped, never smooth"), gait frame
  alternation, patrol reversal — unit-tested without a canvas; the Pixi layer only
  renders poses and pauses its ticker on `document.hidden`.
- **App state**: harness home creation is idempotent, `config.json` is written
  atomically (temp + rename), and an invalid config is *left untouched* while the
  app runs on defaults with the warning surfaced in the status line.

## Mathematical / Statistical Details

Stepped easing: for elapsed time *t*, duration *D*, and *n* steps, progress is
`min(⌊clamp(t/D,0,1)·n⌋/n, 1)` — a staircase function guaranteeing positions land
only on the *n*+1 quantized grid points (verified by exhaustive 7 ms sampling in
tests). Window-bounds sanitization accepts persisted bounds only if some display
work area would contain at least a 100 px grab-handle margin of the window; anything
else restores defaults (the unplugged-monitor case).

## Design Decisions

Recorded one-per-line in `docs/DECISIONS-LOG.md`; the load-bearing ones: Electron
pinned to 37 (Node 20 toolchain vs Electron ≥38's Node 22 requirement), vite pinned
to 7 (electron-vite@5 peer range), `pixi.js/unsafe-eval` so the strict CSP holds
rather than weakening `script-src`, node-pty Windows patches applied in postinstall
(idempotent script, not hand-edited node_modules), and preload kept dependency-free
as an architectural rule.

## Verification

```
npm run typecheck && npm run lint && npm test   # 3 projects · zero warnings · 59/59
npm run dev                                     # floor + live terminal, zero console errors
```

Live-run evidence (captured via `ELECTRON_ENABLE_LOGGING`, details per package in
`docs/PROGRESS.md`): config round-trip `schemaVersion=1`; PTY echo/resize/kill
round-trips against a real conpty PowerShell; floor canvas 448×256 with patrol
reversal and ticker pause/resume across a hide/show cycle; harness home created on
first run and window bounds restored from SQLite on the second.
