# M8.13 — The report you read when nobody was watching

**Date:** 2026-09-08 · **Milestone:** M8, added after the exit run ·
**Branch:** `feature/m8-13-diagnosis` from `origin/main` `06e5991`

---

## 1. Problem / motivation

The M8 exit run stalled during setup — desktop control was denied, so nobody
could press **START THE COMPANY** — and it still produced five findings. Getting
them cost a fresh reader forty minutes of discovering where `EPH_HOME` was,
which panels existed, and what had and had not run.

Every fact it needed was already on disk. None of it was in one place.

The Architect's statement of the need:

> During testing I may not be present at the computer, so the project must
> prepare itself for the scenario that I will have to record the issue properly
> so another agent can see what is working, what is not working, why is it not
> working properly.

So this package is not a feature so much as an **account**. And four of the five
exit-run findings were defects in documents merged hours earlier, which are
fixed here too.

## 3. Implementation approach

### 3.1 Four states, and the fourth is the point

`working` · `broken` · `waiting` · **`not-exercised`**.

A report saying "incidents: ok" because no incident has ever been raised would
be exactly the check-that-cannot-fail this codebase keeps finding, dressed as a
diagnostic. Two passes were already saved from it by a human writing "NOT
exercised" instead of "fine" — the 2026-09-07 live verification, whose §6.3
exists for this reason, and the M8 exit run, which reported six clauses as NOT
EXERCISED rather than banking a vacuous pass.

The rule, in order:

1. a **live** degradation naming this area → `broken`, with its cause, detail and
   repeat count;
2. unless that cause is declared a `waitingCause` → `waiting`;
3. otherwise a log row that **proves** the area did its job → `working`, citing
   the row by kind, event and seq;
4. otherwise → `not-exercised`, saying what *would* exercise it.

A **carried** condition — replayed at boot, true when we stopped, not re-checked
since — never makes a row `broken` on its own. It gets its own section, because
"this was wrong last week" and "this is wrong now" are different sentences.

The probe table is written in the **consumer's** vocabulary, not the producer's:
the incident board folds `event: 'incident-*'`, not `kind: 'incident'`, and
three would-be defect reports on 2026-09-07 were greps on the wrong key.

### 3.2 It stores nothing

The audit found the material already there. `AgoraHealth.runtime` is the M8.2
degradation ring — one row per CAUSE with `count`, `since` and
`freshness: 'live' | 'carried'` — and it already survives a restart. The book of
record already holds every positive event.

What did not exist was any artifact holding them together: the harness writes
`config.json`, `gate-policy.json`, `authority.json`, `breaker-stops.json`,
`github-app.json` and `triggers.json` — all inputs and state, not one of them an
account of what happened.

So this is a **reading**, never a second copy (the M8.9 B14 rule, and
`refute-the-register-not-just-the-code`). Markdown rather than JSON for the same
reason: `log.jsonl` is already the machine-readable ground truth, and a parseable
twin would owe a schema and a validator under invariant §9 for no gain.

### 3.3 No CLI, and the cost is stated

An offline `node scripts/diagnose.cjs` is the obvious shape and was refused
twice over. `scripts/*.cjs` cannot import `src/shared/*.ts`, so it would
re-implement `parseLogLine` and the degradation vocabulary in plain JS — two
things that must agree. A TypeScript runner is a new dependency, which
BUILD-PROMPT §10 makes a must-ask for what is a convenience.

The cost is real: **if the app never starts, there is no fresh report.** It is
paid for by writing often — boot, every sixty seconds, and once more in the quit
path — and by putting the file's own age in its **first line**. Freshness is
something no writer can guarantee; a stale report being *read as current* is the
failure that actually matters, and that one is preventable.

## 4. Mathematical / statistical details

None. `agoPhrase` floors to the coarsest unit a person acts on (minutes → hours
→ days); because `minutes` is already an integer, `< 1` and `<= 0` are the same
predicate, which is what the planted no-op mutant in §6.4 exploits.

## 5. Design decisions

Full list with reasons in `docs/DECISIONS-LOG.md` (2026-09-08). The alternatives
refused:

| Alternative | Why not |
|---|---|
| A JSON report | `log.jsonl` is already the machine-readable truth; a twin owes a schema for no gain |
| An offline CLI | Would duplicate `parseLogLine` in `.cjs`, or add a dependency |
| Two states (ok / broken) | Renders an untouched subsystem as healthy — the exact defect this repo keeps finding |
| Consent as `broken` | It is the designed state; a BROKEN on every healthy first launch teaches readers to skip the column |
| A durable status store | Derived state needs no store; a second copy is a second thing to disagree |

### 6.2 Three defects the FIRST live boot exposed

All three were mine, all three invisible to 4,231 passing tests, and all three
obvious the moment a real boot wrote a real file.

**(a) Withheld consent rendered as `BROKEN`.** It is the designed state. A BROKEN
on every healthy first launch is how a reader learns to skip the column. Fixed
with a fourth verdict declared per probe as `waitingCauses`, so the table stays
the one place that says what a condition *means* — and `consent/unwritable`,
which shares the same source, still reads `broken`.

**(b) "No schedule is armed, by design" — followed by five armed schedules.**
`scheduler.armed()` reports **registered** triggers; the clock that fires them is
behind the consent gate (ADR-0032). On a withheld company that list is a
forecast, not a state, and the heading now says which.

**(c) The rewrite trigger was on the company scheduler.** Whose clock is also
behind the consent gate — so on a machine stuck at that gate, *the state a
stranger is most likely to be in*, the report would have been written once at
boot and never again. It now runs on its own unref'd `setInterval`. **A
diagnostic that stops when its subject stops is not a diagnostic.**

Proved live, against a fresh `EPH_HOME`, consent withheld throughout:

```
Written 2026-09-07T22:31:28.371Z
Written 2026-09-07T22:32:28.373Z     <- sixty seconds later
triggers.json                        <- never created; the company clock never ticked
```

and the corrected report:

```
- consent: NOT GRANTED — nobody is hired and no clock is running, by design
**1 thing(s) are broken right now:**   memory and recall — mempalace ENOENT
**1 thing(s) are waiting on YOU:**     consent — consent/not-granted
**8 of 11 areas are NOT EXERCISED** — … Do not read that as health
## Schedules that would start
_The trigger clock does not start until consent is granted, so none of these are running._
```

### 6.3 A survivor that was a missing test

`carried = conditions.slice()` survived the first mutation pass. "Equivalent" is
the comfortable reading and it was wrong: the carried section states its rows
"were true when the harness stopped and nothing has re-checked them since", and
saying that of a condition true *right now* is a lie — the exact confusion the
two sections exist to prevent. The existing test asserted only the forward
direction. Test added, mutant re-run, killed. Third consecutive package where a
survivor was read rather than patched around, and third where it was a gap.

### 6.4 Mutation pass — 16 mutants, 15 killed, 1 planted no-op survived

The four-state rule in every direction; `kind:event` matching (a fold that
matched on kind alone would report consent as `working` on every machine that has
never been consented to); newest-proof-first; the staleness line; the writer's
never-throws contract; and the two self-descriptions the report makes about its
own limits. The sixteenth is `minutes < 1` → `minutes <= 0` on an integer, which
**survived as designed** — a harness reporting every mutation killed cannot tell
you when it has stopped running your tests.

One mutant (`D15`) referenced a field that does not exist and so failed to
compile; it is recorded as **not a valid mutant** rather than counted as a kill.

### 6.5 The coverage floor caught a design smell

`agora` dropped below its branches and functions floors. The cheap hypothesis was
right: `src/main/diagnosis.ts` was 2/4 functions because `at()` and its clock
default had **no production caller**. The fix was deletion, not a test. The
writer now has no clock at all and renders against the instant its own snapshot
was taken — a clock of its own would have been a second source of time that had
to agree with the first.

### 6.6 Not proved

- **The quit-path write.** Stopping Electron *by process* — which is what the
  README correctly instructs — never reaches `before-quit`. That write is
  covered by the seam test and not by a live run. It matters little: the
  sixty-second cadence bounds staleness at a minute either way.
- **No UI was driven**, again. The report is written by main and read from disk.
