**Date:** 2026-09-07 · **Milestone:** M8, package 13 of 13 ·
**Branch:** `feature/m8-12-exit-review` from `origin/main` `6fdcad2`

> **The exit row is NOT ticked, and this document does not tick it.** M8's exit
> is SRS §6.1's action half on a real repository, performed by *a developer who
> is not the author, from a clean clone, following only the README*, surviving a

## 1. Problem / motivation

Three separate problems, and the first one shapes the other two.

**Booting Ephesus hired an agent.** `src/main/index.ts` computed the reference
engine at the end of boot and called `void artemis.start(orchestratorEngine)`
unconditionally; forty lines earlier it called `scheduler.start()`. A grep of
the whole tree for `consent`, `firstLaunch`, `first-run` or `onboard` returned
three hits, all unrelated prose in comments. There was no consent machinery of
any kind. So a stranger who ran `npm install && npm run dev` had a real `claude`
process spawned under their own account, spending tokens against **their**
subscription — uncapped, because ADR-0029 makes `unbudgeted` the shipped default
— and sixty seconds later the scheduler's first tick fired. On the Architect's
own machine `~/.ephesus/triggers.json` shows `standup`, `retro` and
`gym-metric-check` sharing the timestamp `1788631795998`, so that first tick
fires all three together. This was register item DD-6, carried open for the whole
of M8.

**Two live findings were owed a decision, not a fix.** From the 2026-09-07 live
verification pass: a duplicate `seq: 143` in the Architect's book of record (F1),
and the fact that stopping `npm run dev` leaves Electron alive so two harness
instances can share one home (F2).

**And the exit itself was not runnable.** The README had a setup section (M8.4)
and a "Watching a repository" section, with nothing between them: no sentence got
a stranger from "the app booted" to "a crew is watching my repo", which is where
§6.1 *begins*. §6.1 also has clauses a tired person skips at 11pm — "filed the
required memo **if** the fix crossed policy", "with zero un-gated destructive
actions" — and no script said where their evidence lands.

## 3. Implementation approach

### 3.1 The decision is pure, and it is not in `index.ts`

The known risk this package carries is the opposite of M8.11's: that one was
deletion, this one is **additions on the boot path**, which is where a test
cannot easily go. `index.ts` boot wiring has produced three dead-code findings in
this repository — the Herald, M7.2's inert trigger, M7.7's silent standup — every
one of them behind a green suite, because nothing short of a real Electron boot
could reach the code.

So the work is split three ways:

- **`decideConsent`** (`src/shared/consent.ts`) is pure. Record in, verdict out.
- **`CompanyStart`** (`src/main/consent.ts`) owns the ordering — persist, then
  hire, then start the clock, at most once per process — with `record`, `save`,
  `disclose`, `hire`, `startSchedule`, `report` and `clear` all injected.
- **`index.ts`** constructs it and calls `boot()`.

**Production call path** (ENGINEERING-STANDARDS §6.7): `src/main/index.ts:3328`
`companyStart.boot()`, on the object constructed at `:2961` with
`hire: hireOrchestrator` (`:2872`) and `startSchedule: () => scheduler.start()`
(`:2968`). The grant path is `src/main/ipc.ts:611` → `deps.consent.grant()` →
the same private `startWork()`, reached from `src/preload/index.ts:74` and the
one button in `ConsentGate.tsx`.

### 3.2 Consent covers the company starting work, not just the hire

This is the decision the package turns on, and refusing to leave it implicit is
half of it. "The gate guards the hire" and "the gate guards the company starting
work" are different products. Both `artemis.start` and `scheduler.start()` wait.

The clock is withheld **whole** rather than per-trigger, even though
`Scheduler.enabled()` already exists (it is how ADR-0018's company modes reach
the scheduler) and would have been the smaller diff. A trigger armed later by a
restored activation (ADR-0027) would be armed *unguarded*, because nothing would
have added a predicate to it, and nothing would report the day that started being
true.

What is deliberately **not** covered: the boot-time Harbor probe and its first
`gh` ingest. They read; they spawn nothing, spend no tokens, and raise no
incident without the scheduler. Gating a read-only local command would tell a
stranger their consent was needed for something it was not. The live run confirms
this — the refusing boot still wrote eleven `remote` rows.

### 3.3 Absent means ASK — the M8.4 trap, restated

`ensureHarnessHome` seeds a file only when it is **absent** (`home.ts:57`),
deliberately: `~/.ephesus/` is the Architect's copy and the harness must never
overwrite a decision they made. The consequence bit for real three days before
this package — the Architect's `gate-policy.json` predated DD-1 and had never
received it, sitting silently looser in three places, including having no
`outbound` rule at all.

A consent record has exactly that shape. **Every** install that exists today has
none. So `undefined` must read as "ask": not "assume yes" (a gate that refuses
only on machines nobody has), and not a durable "no" (a refusal nobody could
lift). Only a grant is written; a decline is the absence of one, because the
withheld state *is* the question and it stays on screen until answered.

**Corrupt reads as ask too**, and this falls out of the existing design rather
than being added: `configSchema` is strict, a malformed consent block invalidates
the whole file, `home.ts` runs on `defaultConfig`, and `defaultConfig` carries no
consent. A damaged file must never be the thing that authorises spending.

The upgrade path is tested against a `config.json` written to disk in the
pre-M8.12 shape and read back through the real `ensureHarnessHome` — not against
a fresh home. That is the `engine-honesty.test.ts` pattern, for the same reason.

### 3.4 The disclosure is computed, never written

`consentSentences` builds every line from a `ConsentDisclosure` that main
assembles from live facts: the engine from the same `orchestratorEngineNow()` the
hire uses, the cadences from `scheduler.armed()`, the ceiling from
`gate-policy.json`. A consent screen whose promises were prose in a component
would go stale the first time a trigger was added, and **consent obtained against
a stale description is not consent**.

`armed()` excludes a trigger its own `enabled()` currently refuses — the Stoa
cadence cannot fire in `directed`, the Harbor ingest cannot fire with nothing
watched — because naming them would over-promise exactly as badly as omitting a
live one would under-promise.

One line is worth calling out: when there is no daily ceiling, the disclosure
says so **out loud**. `unbudgeted` is the shipped default and it is precisely the
fact a person granting spend authority needs; omitting the line when there is no
limit would make the most permissive configuration the quietest one.

### 3.5 The record carries which disclosure was agreed to

`{ grantedAt, terms }`. `terms` is the `CONSENT_TERMS_VERSION` the grant was
made against, so widening what consent covers can ask again rather than silently
carrying a narrower agreement onto new behaviour. A grant against a *newer*
version than this build asks about is honoured — that is a downgrade, and
re-asking somebody to consent to a subset of what they already allowed is an
interrogation rather than a safeguard. `grantedAt` is never rewritten: it says
when consent was *first* given.

### 3.6 F1 — the cursor is a position, not a threshold

`EventLog.read` filtered every line on `entry.seq > afterSeq`, which is correct
only while `seq` strictly increases in file order.

**The cause is in the writer, and it was found by reading it rather than
guessing.** `EventLog.seq` is an in-memory counter recovered at `open()`. Two
harness processes pointed at one home each recover the same high-water mark and
both stamp `highest + 1`. The class comment claimed `O_APPEND` "covers the case
of a second harness process pointed at the same home" — true of the bytes, false
of the counter — and it now says so. F2 is the mechanism that produced it.

**What decided "tolerate" over "accept as a scar" is who loses the row.**
`BriefingJob.gather(sinceSeq)` pages from a cursor, so a hidden row is a hidden
event in the standup — and SRS §6.1 asks for *"the next briefing narrates the
incident accurately from the log"*. The exit criterion's own evidence path was at
stake, which makes this not a cosmetic wart in the record.

The new rule: skip the leading run of entries at or behind the cursor; once the
walk has begun returning, return everything after it in **file** order. On a
strictly increasing log the two rules agree line for line, including the case of
a leading `seq: 0` row (which the schema permits).

**Two residuals, taken deliberately and pinned by tests.**

1. A cursor sitting on the row *immediately before* the duplicate still misses
   it, because the position is found by the first entry ahead of the cursor and
   there is none until after the duplicate. That is **one** cursor value, down
   from three. Closing it means "begin returning when the seq goes backwards",
   which re-delivers the row to every later cursor as well unless qualified by
   the highest seq seen so far — three interacting conditions in the reader every
   consumer shares, to recover one row on one cursor value, at the cost of a
   subtle "delivered at most once" invariant. A consumer paging continuously
   receives the row in an earlier batch and never holds that cursor.
2. `sourcesFrom` skips whole segments by filename, so a duplicate inside an
   already-passed segment is still lost. Opening segments to find out is exactly
   the cost rotation exists to avoid.

### 3.7 F2 — documented, and the design half asked rather than built

The README's setup section and `docs/EXIT-M8.md` §4 both say to stop Electron by
process, in PowerShell and POSIX form, with the reason. Whether the harness
should **refuse to boot** on a home another instance holds touches ADR-0004's
single-committer rule, needs a stale-lock policy and a refusal message, and would
be the first thing that can stop the app from starting. That is a §8.3 must-ask,
not something to build on this package's own initiative — it is in the session
report with options and a recommendation.

## 4. Mathematical / statistical details

Only one figure here is measured rather than chosen, and it is the coverage
ratchet. `scripts/check-coverage.cjs` raises a floor only after
`corroboratingRuns` = 3 runs on one production tree hash, and only to the
**metric-wise minimum** across the window. Three runs of tree `ffa20b55b23a`
agreed to the hundredth on every row, which is the same spread (0.00) the M8.0
baseline recorded for n = 3 on this platform. `home` rose 55.43% → 71.93% lines
because `src/shared/consent.ts` joined the subsystem well covered and
`src/main/config.ts` moved out of the untested-module record. `panels` and
`company` rose by smaller amounts from the new component and `armed()` tests.

`everyPhrase` rounds to the coarsest unit a person reads (minutes → hours →
days) via `Math.round`. It is a disclosure, not a clock; the planted no-op mutant
in §6.5 exploits the fact that `minutes` is already an integer, so `< 1` and
`<= 0` are the same predicate.

## 5. Design decisions

The full list with reasons is in `docs/DECISIONS-LOG.md` (2026-09-07, M8.12 D1–D5
plus the two findings) and the consent decision is [ADR-0032](../adr/ADR-0032-the-company-asks-before-it-starts.md).
The alternatives that were considered and refused:

| Alternative | Why not |
|---|---|
| Defer consent to M7b with onboarding | M8's exit measures the first afternoon; the review would have been conducted against the behaviour it exists to find |
| Gate only the hire | Leaves the register's second complaint entirely intact — standup, retro and the metric check still fire on the first tick |
| Per-trigger `enabled()` predicate | Smaller diff on an existing seam, but a trigger armed later by a restored activation would be armed unguarded |
| A separate `consent.json` | Invariant §9's own reasoning: `config.json` already carries durable, schema'd, validated state the app did not compute |
| Persist a decline as well as a grant | Both a decline and an absence mean "not granted, keep asking"; a stored "no" only adds a state to clear |
| F1: accept as a one-off scar | A cursor-hidden row is a hidden event in the standup, which is §6.1's own evidence path |
| F1: full tolerance for every cursor | Three interacting conditions in the shared reader, and a re-delivery loop unless carefully qualified, to recover one row on one cursor value |
| Exit script inside TEST-STRATEGY | That document says what tests are owed; this is an operator runbook for one human doing one run by hand |

mutation runner fail open.

### 6.6 What was NOT proved

## 7. Making the exit runnable by a stranger

The README's gap was between "Setting it up" and "Watching a repository": nothing
got a person from *the app booted* to *a crew is watching my repo*, which is where
§6.1 begins. Two sections were added in the README's own voice rather than
rewriting it.

**Say go** — the consent banner, what it discloses, that a grant takes effect in
the same window, and that everything else stays readable while it is closed. Plus
**stopping it**: by process, not by the wrapper, in both shells (F2).

**Your first crew** — the four steps nobody had written down. Check the
orchestrator came up and what it means if she did not; what a profile *is* and
which two ship; that `gh` must be authenticated or the crew ingests nothing and
says so; that the activation screen shows the whole plan before anything starts;
and how to take it down again.

**`docs/EXIT-M8.md`** is the script. It opens with who may run it and what it
means if you cannot — a run by the author is a rehearsal, and saying so in the
record is part of the job. Then setup, the ceiling to set *before* walking away,
the break to introduce, and where the restart goes. For each §6.1 clause it names
the log `kind`/`event`, the panel, and the file. The two clauses that get skipped
are called out:

- *"filed the required memo **if** the fix crossed policy"* gets a three-step
  check, and — this is the part that matters — **"no memo was required, because
  no gate of a memo-triggering class opened" is a pass, and silence is not.**
- *"with zero un-gated destructive actions"* gets the only method that works:
  enumerate every gate that opened, then go looking for what should have opened
  one and did not, with the `git reflog` commands to do it.

It also carries the search rule that saved three false findings on 2026-09-07 —
search for what the **consumer** calls it — and a one-liner to check the log's
own seq contiguity before trusting anything read from it.

## 8. What remains, and it is the exit itself

**The M8.12 row is ticked for the work the Architect attached to it. The M8 exit
row is not, and must not be.**

What is still owed, in full:

- **a developer who is not the author** — this package's author cannot satisfy
  the clause by running it;
- **a clean clone** — every setup defect this milestone found was invisible on a
  machine that already had the files;
- **the README alone** — anything they cannot do from it is a finding, and the
  finding is worth more than a pass;
- **a deliberate restart mid-run** — M8.8 built restart survival and nothing has
  ever exercised it during real work.

What was made ready for that person: a first launch that asks before it spends, a
README that gets them from `git clone` to a crew watching their repository, a
script that tells them what to break and where each answer lands, and a book of
record whose readers no longer quietly drop a row.

What could not be established here: whether any of that is *enough*. That is
what the run measures, and it is the Architect's to tick afterwards. M7's exit
has been open since 2026-09-01 on the same criterion; the same run is owed to
both.
